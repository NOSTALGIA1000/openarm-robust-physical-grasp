# 全库回溯：容差曲线复核、分类 bug 的真实影响、探测超时与偏置无关

日期：2026-09-06
范围：`docs/results/physics_grasp/` 下 41 个批次、**470 次记录**，无新试验，纯回溯分析。

---

## 1. 为什么要复核

两个疑点挂了很久：

1. `detector_timeout` 这一类别是后期才加的（stage18）。在此之前，探测器从未报数的试验会被记成 `planning_failure`。**已发表的容差曲线里有多少是这种误记？**
2. 若探测超时随偏置升高而增多，那么"高偏置下成功率下降"就可能部分来自探测失效而非精度不足，**容差数字会被这个混淆项污染**。

## 2. 回溯判据

在 `stage16_limits2/fb_y128_1` 的记录里找到现场：

```
- Result: `planning_failure`
- Samples: `0`
- Max elevation: `0.0000 m`
## Stage times (simulation seconds)
（空）
```

`sample_count == 0` 且 `timed_out == True` 且 `gripper_ok == False`——物理仿真一步没跑，不可能是规划失败。真正的规划失败都有非零 `max_elevation`（接触噪声）和完整阶段耗时。

以此判据扫全库：

**470 次记录中应重判的仅 2 次**——`stage16_limits2/fb_y128_1` 与 `stage4_relative/rh_b096_1`。

分类 bug 是真的，但**影响范围远小于担心的程度**，历史曲线不需要重画。

## 4. 三点结论

**（a）探测超时与偏置无关。** y 向 41 次里 4 次超时，分布在 128、248、256、320——低偏置区有，中段 192–240 共 18 次一次没有。x 向 13 次全无。**没有随偏置上升的迹象**，容差数字不被这一项污染。n 小，不能排除弱趋势，但担心的那个混淆项没有证据支持。

**（b）两条悬崖的机制不同，此前混为一谈过。**

- **x 向**：96mm 尚有 83%，112mm 起全部 `planning_failure`——**IK 无解**，与探测精度无关。这与已记录的"x≥112mm 不可达"一致。
- **y 向**：208–240mm 是 12/12 满分，288mm 掉到 0，且失败形态是 `unilateral_contact` 3/4（够到了、碰到了，只有单侧夹住），320mm 才变成 `no_contact`。**这是残差随偏置放大的签名，不是可达性问题。**

**（c）"256mm"这个主线数字站在悬崖边上。** 256mm 实测 4/7（57%），而 208–240mm 是 12/12。更稳的表述是：**满分区间到 240mm，256mm 为过渡区，288mm 已失效。**
