# OpenArm 视觉标记定位：纯深度图下不可行

日期：2026-09-05
状态：**方案被否定。原理成立，但仅有深度通道时标记无法与小臂分离。**

原始数据：`docs/results/physics_grasp/stage25_marker/`
前置：[夹爪测量稳定性](2026-09-05-openarm-gripper-feature-stability.md)

---

## 1. 动机

前一文档确认了一个结构性冲突：ROI 窗口越小测量越稳（55→30 px 使残差跨度 30.6→3.1 mm），但窗口中心由 TF 投影得到，而 TF 携带的正是待抵消的手眼偏置，因此窗口会随偏置增大而脱靶（64 mm 时偏约 54 px，30 px 半径必然落空）。

**若窗口中心能从图像本身获得，循环依赖即被解除。** 为此在 MJCF 的 `openarm_left_hand` 上加了一个视觉标记球（`contype/conaffinity=0`，无质量，不在 URDF 中因而不影响 MoveIt 规划），探测器改为先在图像中定位标记、失败再退回 TF 投影。

## 2. 三轮失败与一次方法反省

| 轮次 | 改动 | 结果 |
|---|---|---|
| 1 | 标记挂 `hand` 局部 −0.15，深度带 0.48–0.58 | 选中图像左边缘杂物（u=6~29，手在 u≈202） |
| 2 | 改挂 −0.0735（修正高度算错），带 0.50–0.56 | `detector_timeout`，随后一次仅偶尔命中 |
| 3 | 加圆度判别（≥0.72） | **全部候选圆度 0.26–0.66，无一通过** |

高度算错的原因：`hand` body 在 hover 时位于 z≈0.5965（TCP 0.5165 加 hand-to-TCP 的 0.08），我误按 TCP 高度推算，把标记放到了深度 0.45，正落在小臂上。

**方法反省**：三轮都是「改参数—重跑」，每轮约 2 分钟并附带判断风险。而 `hand` mesh 的 `pos="0.0 0.005 -0.6585"` 早已提示手的几何范围无法从 body 原点推断。**先读一帧深度直方图**本可一次看清，却排在了三次猜测之后。

## 3. 决定性数据：小臂占满标记所需的深度空档

在手臂进入视野时抓取直方图（前一次抓帧过早，画面里只有物体与桌面，说明不了任何问题）：

```
0.40-0.42 : 3360        ← 小臂
0.42-0.44 : 2696
0.44-0.46 : 2125
0.46-0.48 : 1299
0.48-0.50 : 1512
0.50-0.52 : 1504
0.52-0.54 : 1049        ← 标记应在此处
0.54-0.56 :  433
0.56-0.58 :  245
0.58-0.60 :   88
0.60-0.72 :    0        ← 空档
0.72-0.74 :  552        ← 物体
```

**小臂在 0.40–0.60 连续无空隙**，标记位于 0.53 正在其中，两者在深度图上连成同一连通域——这正是圆度全部偏低的原因：测到的不是球，是球与小臂粘连后的形状。全域扫描 0.42–0.70 未检出任何 `circ>0.6` 的团。

可用空档只剩两处，均不实用：

- **深度 < 0.40**：需标记高出小臂 0.2 m 以上，支杆长度不现实；
- **深度 0.71–0.72**：手与物体之间，仅约 10 mm 宽，稍有姿态变化即失效。

## 4. 结论

**在仅有深度通道的条件下，视觉标记无法与手臂分离，方案不可行。**

根本原因是深度图中"标记"与"手臂"没有本质差别——两者都只是距离值，唯一可用的区分维度（深度）已被手臂占满。**要让标记可用需要 RGB 通道**（颜色分割），或改用手臂语义分割。

作者推荐该方案时默认"标记总能被识别"，未先核对深度通道是否具备可分离性，这是选型阶段的疏漏。

## 5. 处置

- `use_marker_roi` 默认置 **False**，代码保留；
- 标记 geom 保留在 MJCF：它无碰撞、无质量、位于 0.53 不落在夹爪深度带 0.594–0.710 内，对现有流程无影响，且加入 RGB 通道后即可启用；
- 深度直方图诊断脚本存入 `tools/experiments/depth_hist.py`，供后续排查复用。

## 6. 仍然待解

前一文档的结构性冲突**未解决**：ROI=30 px 精度好但抗偏置差，ROI=55 px 反之。剩余可行路径为**两段式自适应半径**（先大窗定位、再小窗精测），它不依赖新传感通道。
